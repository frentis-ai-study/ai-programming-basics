# W12 섹션 2 · 검증한 코드에서 거꾸로 작성한 수업용 요청문

> 이 문서는 `weather.py`를 실행·검증한 **뒤** 학생이 확인할 조건을 요청문으로 묶은 연습 자료입니다. **이 요청문으로 현재 v3 코드를 생성했다는 뜻이 아닙니다.** 원래 요청문은 구볼트의 기존 `W12-날씨수집기/프롬프트.md`에 별도로 보존되어 있으며 이 예제 폴더에는 포함되지 않습니다.

## 첫 요청 — 만들 동작과 확인 방법을 함께 쓰기

```text
서울의 날짜별 최고·최저기온을 CSV와 그래프로 저장하는 Python 프로그램을 만들고,
제가 따라 실행할 명령과 결과를 확인할 방법도 알려 주세요.

1. 서울 좌표 37.57, 126.98을 쓰고, Asia/Seoul 시간대에서 지난 7일과 오늘을 조회해 주세요.
   Open-Meteo의 일별 최고·최저기온 항목을 사용하고 API 응답은 10초 이상 기다리지 마세요.
2. 인터넷 없이 같은 결과를 반복 확인할 수 있도록 JSON 예제 파일을 읽는 방식과
   현재 API를 조회하는 방식을 별도 옵션으로 제공해 주세요.
   JSON 예제는 원본 API 응답이 아니라 보관 CSV에서 재구성한 입력으로 명시해 주세요.
3. 날짜·최고·최저기온 배열의 같은 순번을 한 행으로 묶고,
   날짜와 기온 값이 유효하지 않거나 길이가 다르면 저장하지 말고 오류를 알려 주세요.
4. date,max_temp,min_temp 열의 weather.csv와 두 계열을 구별할 수 있는 weather.png를
   지정한 출력 폴더에 저장하고, 며칠치를 어디에 저장했는지 출력해 주세요.
5. API가 응답하지 않거나 오류를 보내면 성공했다고 말하지 말고 오류를 알린 뒤 종료해 주세요.
   이전 실행 파일이 있다면 새 결과로 덮어쓰지 마세요.

작성한 코드를 실제로 실행해 CSV의 날짜·기온 값과 그래프를 확인하고,
실패 시험은 실제 외부 API 장애인지 로컬에서 만든 통제 시험인지 구별해서 보고해 주세요.
```

## 수업에서 확인할 내용

- **입력 선택:** `--fixture`는 제공한 JSON 파일을 읽고, `--live`만 현재 API에 요청합니다. 두 결과의 날짜가 같다고 가정하지 않습니다.
- **중간 처리:** `daily.time`, `temperature_2m_max`, `temperature_2m_min`의 같은 위치를 한 행으로 묶습니다.
- **성공 기준:** CSV 8개 날짜 행(제공한 보관 예제의 경우)과 PNG의 날짜·범례를 실제로 열어 대조합니다. 라이브 호출의 날짜 수는 API 응답에 따라 따로 셉니다.
- **실패 기준:** 로컬 HTTP 503 통제 시험에서 종료 코드·오류 안내·기존 파일 보존을 확인합니다. 외부 API의 실제 장애를 보았다고 주장하지 않습니다.
- **AI 사용 시 주의:** AI가 이 문장대로 만들었다고 해도 사용자가 코드를 실행하고 파일의 실제 내용을 검사하기 전에는 ‘완성’이라고 판단하지 않습니다.

실행 가능한 정답을 고정하려는 요청문이 아니라 **검사할 기준이 있는 대화 출발점**입니다. 다른 AI 도구가 내놓는 답은 코드와 파일로 따로 대조해야 합니다.
